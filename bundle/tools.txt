# The tools bundle (roadmap 2.0, docs/plan/install-speed.md): every core tool that has a portable
# Windows build, fetched from its upstream release by CI (build/bundle), repacked as one zip per
# tool and published with omawin's release. The install downloads them all at once and unpacks
# them side by side into %LOCALAPPDATA%\omawin\tools\<name>: no winget, no installers, no admin.
# Omarchy does the same with its ISO's offline package cache.
#
#   <name> | <source> | <asset> | <bin> | <winget id it stands in for> | <home> | <later>
#
#   source  github:<owner>/<repo> (its latest release), node-lts, zig-stable
#   asset   a regex for the release file's name; "=> <name>" renames a single-file asset (an
#           .exe, or a .gz holding one)
#   bin     the folder inside the tool that goes on the PATH ("." for its top, "-" for none)
#   winget  the core package it replaces (packages.ps1): that one isn't installed through winget
#   home    where it goes instead of tools\<name>, under %LOCALAPPDATA% (a tool other scripts
#           already look for in its own place)
#   later   "later": the install doesn't wait for it; it finishes unpacking in the background
#           (a big one nothing needs at once: zig, for Neovim's first parser build)
