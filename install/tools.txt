# The tools bundle (roadmap 2.0, plans/install-speed.md): every core tool that has a portable
# Windows build, fetched from its upstream release by CI (build/bundle), repacked as one zip per
# tool and published with omawin's release. The install downloads them all at once and unpacks
# them side by side into %LOCALAPPDATA%\omawin\tools\<name>: no winget, no installers, no admin.
# Omarchy does the same with its ISO's offline package cache.
#
#   <name> | <source> | <asset> | <bin> | <winget id it stands in for> | <home> | <flags>
#
#   source  github:<owner>/<repo> (its latest release), node-lts
#   asset   a regex for the release file's name: a zip, or with "=> <name>" a single file renamed
#           (an .exe, or a .gz holding one)
#   bin     the folder inside the tool that goes on the PATH ("." for its top, "-" for none)
#   winget  the core package it replaces (install/packages.ps1): that one isn't installed through winget
#   home    where it goes instead of tools\<name>, under %LOCALAPPDATA% (a tool other scripts
#           already look for in its own place)
#   flags   later: the install doesn't wait for it, it finishes unpacking in the background (a
#           big one nothing needs at once); keep:<pattern>[,<pattern>...]: only the files whose
#           name matches one (the font: the four faces a terminal and an editor use, of the one
#           family omawin names, "JetBrainsMono NF", not all 96: ~10 MB of 135); sfx: a 7-Zip
#           self-extractor shipped as it is, which the PC runs to unpack (Git for Windows' portable
#           build: its LZMA is ~60 MB where a zip of what's inside is ~160)
